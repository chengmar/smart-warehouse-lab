# 课堂演示与小组提交

## 用一笔业务讲清楚系统

登录主管账号，在调度总览点「登记入库」。选择挂耳咖啡和 A-04 货位，填一个新批号，效期填明天，数量填 11。当前演示库使用未来日期的种子批次，这样刚入库的批次通常最早到期。到「库存货位」按刚填的批号搜索，确认在库 11、预留 0。

在「出库订单」创建一张 4 盒挂耳咖啡的订单，找到该客户，点「查看订单 → 分配库存」。打开详情核对实际分配的批号和货位。如果有其他更早到期的批次，以详情中显示的分配为准。分配只增加预留，确认拣货时数量不动，复核出库后才扣掉实物和预留。

进入「物流跟踪」，等后台处理出库事件。打开这张订单的运单，依次模拟揽收、签收。回到「流水与核对」点「运行核对」，查看库存数量、有效预留和流水是否一致。点「冷链监测」上报 9.1℃，观察一次越界采样如何生成可由主管处理的告警。设备和承运商均为本地模拟端。

## 三项可单独提交的小任务

|建议领取人|内容|交付及验收|
|---|---|---|
|zkdsbbb|库存 CSV 增加计量单位|修改导出，核对两种单位。[任务 #1](https://github.com/chengmar/smart-warehouse-lab/issues/1)|

|第三位同学|库存表打印样式|打印预览隐藏导航和按钮，核对分页。[任务 #3](https://github.com/chengmar/smart-warehouse-lab/issues/3)|

主实现由组长审核合并后，每位成员从最新 main 新建自己的分支，用本人账号提交改动和 PR，在描述中写明关联的 Issue 及自己实际验证的结果。组长根据已合并的提交和评审填写课程贡献记录。任务认领本身不计为完成。

## 组长审核

在 PR 的 Files changed 查看改动，在 Checks 查看 SQLite、浏览器和 MySQL 结果。核对后进入名为「仓库所有者审核」的 Actions 运行，选择 Review deployments → owner-review → Approve and deploy。该步骤只记录 chengmar 对本次提交的批准。回到 PR 检查当前提交，组长决定是否合并。PR 有新提交时重新核对对应的审核任务。
